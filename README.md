# Twin Mode Dist — эмуляция Boss DS-2 Turbo Distortion

Схемотехническая модель педали DS-2 (плата ET 7510952000) под JUCE 9: VST3, AU (на macOS) и Standalone.
DSP-ядро лежит в одном заголовочном файле без зависимостей, его можно подключить к любому C++ фреймворку.

```
Source/DS2Model.h          ядро: вся схема, режимы Turbo, решатели диодов
Source/PluginProcessor.*   обёртка JUCE: параметры, оверсемплинг 2x/4x/8x
tests/render.cpp           офлайн-рендер float32 через ядро (без JUCE)
tests/analyze.py           АЧХ, гармоники, алиасинг, щелчки, демо-WAV
```

## Сборка

Нужны CMake 3.22+ и компилятор C++17. JUCE 9.0.4 скачается автоматически.

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --target TwinModeDist_VST3
```

Готовый VST3 будет в `build/TwinModeDist_artefacts/Release/VST3/`. Если JUCE у вас уже скачан,
добавьте `-DJUCE_DIR=/путь/к/JUCE`. На Linux нужны пакеты, перечисленные в `docs/Linux Dependencies.md` в репозитории JUCE.

## Параметры

| Параметр | Что делает |
|---|---|
| Dist, Tone, Level | 0–10, как ручки педали (полдень = 5) |
| Turbo | I / II |
| Input Trim | калибровка входа: модель считает, что 0 dBFS = 1 В на входе педали |
| Output Trim | общий уровень |
| Oversampling | 2x / 4x (по умолчанию) / 8x. Меняет латентность |

## Что моделируется

По схеме, блок за блоком:

1. Входной буфер и пара диодов D14/D15 перед бустером.
2. Бустер Q22. Из-за смещения через R63 коллектор сидит примерно в вольте от насыщения, поэтому одна полуволна клипуется жёстко, а другая мягко. Отсюда чётные гармоники.
3. **Turbo I** (открыты Q14, Q20, Q10): полный диапазон идёт на ОУ, в обратной связи стоят D8/D9 с C34 (мягкий клиппинг верхов), после тембра бридж-Т вырез около 1 кГц (−6 дБ).
4. **Turbo II** (открыт Q15): на вход ОУ идёт сумма резонансного Sallen-Key на Q23 (пик около 1 кГц) и верхов через C41/R64. Низ подрезан, мягкого клиппинга нет, ОУ раскачивается до жёсткого клиппинга на D11/D12. Получается громче и «носовее».
5. Дискретный ОУ на Q16–Q19: DIST как реостат 250k, басовый срез в ноге R54/C33, C32 и ограничение полосы усиления. Выход у ОУ несимметричный.
6. Жёсткий клиппер R57 + D11/D12. Он решается **вместе** с тембровым каскадом Q13, потому что тембр его нагружает.
7. Тембр — инвертирующий каскад с регулятором верхов в духе Баксандалла (R58 15k, R46 33k, VR2 100k, C37 6.8n на движке).
8. Q12 и полочный срез верхов (R42/C26/R41/C25), затем Level с учётом нагрузки.

Распределение блоков по режимам я проследил по логике переключения: SW1 → инвертор Q9 → Q14/Q20/Q10, и Q8 → Q15.

Линейные цепи переведены в цифру билинейным преобразованием из аналоговых передаточных функций, конденсаторы рядом с нелинейностями — трапецеидальными компаньон-моделями. Диодные уравнения решаются точно: через функцию Райта ω с одной ньютоновской доводкой, в среднем 1 итерация на решение.

## Что подобрано, а не прочитано

Всё, что помечено `[assumed]`, находится в `DS2Model::Config`:

- уровень входа (0 dBFS = 1 В);
- ВАХ диодов (модель 1N4148, она близка к 1SS133);
- коэффициент усиления Q22 и его запас по размаху;
- GBW дискретного ОУ (1 МГц) и его размах (+3.0 / −2.3 В);
- кривые потенциометров (DIST «D» — 10% в полдень, LEVEL «A» — 15%);
- коэффициент передачи повторителя Q23, который задаёт добротность резонанса.

Если есть живая педаль: прогоните через неё синус-свип и DI-запись в режимах I и II на нескольких положениях DIST, затем подстройте эти поля, сравнивая с `tests/analyze.py`.

## Что проверено

- pluginval 2.0 на строгости 10 проходит без ошибок (частоты 22.05–192 кГц, блоки 1–2048, фаззинг параметров, отсутствие аллокаций в process, сохранение состояния).
- Собранный VST3, загруженный в хост, совпадает с офлайн-рендером ядра: RMS одинаковый, корреляция выше 0.998, октавные полосы в пределах 0.03 дБ.
- При переключении Turbo и движении DIST щелчков нет: используется короткий провал громкости и сглаживание параметров.
- Ядро: ~5–7% одного ядра CPU на моно-канал при 4x на слабом облачном сервере.

## Проверка без JUCE

```bash
cd tests
g++ -std=c++17 -O2 render.cpp -o render
python3 analyze.py ./render out/      # нужны numpy, scipy, matplotlib
```

## Использование ядра в своём коде

```cpp
ds2::DS2Model m;
m.setDist (0.7f); m.setTone (0.5f); m.setLevel (0.5f); m.setTurbo (2);
m.prepare (sampleRate * 4);          // частота ПОСЛЕ оверсемплинга
m.process (oversampledData, numOversampledSamples);
```

Ядро ждёт уже передискретизированный сигнал (рекомендуется 4x) и включённый flush-to-zero.
